4. NOISE / ALERT-QUALITY DEFECTS — this is itself the bug

The nightly nuggets ERROR is structurally guaranteed to fire again tomorrow, for the wrong reason. build_report escalates to severity="error" on memory.events max > 0. Under cgroup v2 that counter increments on every successful reclaim under a hard memory.max. With MemoryHigh=infinity and a 6 GiB cap the job peaks at 5.5 GiB against, a nonzero value is the expected steady state, not a fault — oom and oom_kill were both 0. So #1602 repaired one always-firing predicate and a second one sits directly behind it. Split the loop: keep error for oom/oom_kill, demote memory.events max to informational (it's already in the rendered body). The honest throttling signal is memory.events high, which is checked separately and correctly and will stay 0 while MemoryHigh=infinity.

Meanwhile the condition that actually matters gates nothing. Zero demos landed on three consecutive nights and builds_ok is not an escalation trigger. The report escalated on cgroup bookkeeping and stayed silent on delivery. That inversion is the single worst property of this alerting surface.

The "YouTube Tutorial Interrupted" warning is currently a 100% false promise. It's emitted optimistically at retry-queue time ("Automatic retry attempt 2/3 has been queued") and there is never a follow-up — zero youtube_tutorial_failed notifications exist in the ledger since 07-31, because the reaper finalizes these runs with no surface by explicit design. That contract was correct when it only caught genuinely outcome-less orphans; it now silently absorbs a deterministic, repeating pipeline failure. Fix: emit youtube_tutorial_failed (severity error, which _DELIVERABLE_SEVERITIES mails) when finalizing a run whose latest attempt_number > 1 — i.e. one the operator was already promised a retry on. Keep the no-surface path for attempt-1-only orphans.

A HIGH-severity item in this batch was manufactured by a name collision. HooksService.finalize_stale_youtube_runs (dead) vs stuck_run_reaper.finalize_stale_youtube_hook_runs (live, wired, working) sit in adjacent code. The triage agent grepped the dead one, found no callers, and declared the live safety net fictional. Deleting the dead method is a two-line change that removes a trap which has already cost one false high-severity escalation.

Emails cannot be triaged without SSH. Every alert in this batch required reading journald, sqlite, and build transcripts on the box to find out what actually happened — because the discriminating fields live only in metadata and are filtered out by a global allowlist. Item F is trivially cheap and pays for itself on the next alert.
