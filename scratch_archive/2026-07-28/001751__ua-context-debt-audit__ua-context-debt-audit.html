1 · TL;DR verdict

CLAUDE.md is mechanically healthy but rhetorically bloated, and it is not the biggest line-item. Of ~75 concrete references checked, only 3 are dead or misleading — unusually good. The real debt is (a) one capability documented that no longer exists (here-now, 13% of AGENTS.md), (b) the scratchpad mechanism stated three times across the two files, (c) changelog archaeology baked into rules, and (d) 95 project skills + 25 agent definitions whose descriptions load into every session — the estate-wide usage assessment (Mon 2026-07-27) found ~79% of standing skill tokens earn zero pulls.

Anthropic's 80% cut does not transfer here. Because GLM lanes consume the same files, the realistic safe trim on CLAUDE.md is ~35–45% by weight — dedupe, de-archaeology, and single-homing — while keeping every judgment-dependent rule GLM still needs spelled out.

2 · What /doctor could and couldn't do

  • VPS CLI claude doctor (v2.1.220, in /opt/universal_agent): installation clean. Three "invalid settings" warnings on .mcp.json (missing AGENTMAIL_API_KEY, ZAI_API_KEY×2) are false positives — those ${VAR} placeholders resolve at runtime via the Infisical bootstrap, by design. Remote Control not signed in (expected; headless box).
  • Full in-session /doctor (the one with the CLAUDE.md trim check, v2.1.206+) is interactive-only — it draws a checkup screen and waits for confirmation. Headless -p runs hung until killed on both VPS (also blocked by no OAuth login for print mode) and desktop. Docs confirm the design.
  • So this page is the hand-built equivalent: a mechanical reference sweep (subagent, ~75 refs verified against the checkout) plus a manual derivability classification of every CLAUDE.md section. To get the native trim check, run /doctor in an interactive claudereal session in the repo — it will propose fixes you confirm one by one.

3 · The governing constraint: GLM shares this context

Kevin's point, confirmed in code: the "delete the rules, trust the model's judgment" thesis assumes a Claude 5-class model on the other end. UA's autonomous lanes don't have one:

  • agent_setup.py::setting_sources=["project"] and main.py — Agent SDK sessions load the project CLAUDE.md, all 95 skill descriptions, and .claude/agents; in-process principals (Simone, Atlas) run on ZAI/GLM.
  • Cody / all VP per-task CLI subprocesses default to ZAI (cody_mode.py::_HARDCODED_FALLBACK_MODE = "zai") and load the same files from /opt/universal_agent.

Consequence: the floor of explicitness is set by the weakest model reading the file. Trim what is derivable by any competent model (duplication, archaeology, generic philosophy) and what is mechanically dead; keep every explicit behavioral rule the GLM lanes rely on. If a rule is only needed for GLM, the alternative to deletion is relocation — inject it via the SDK system_prompt in the GLM lanes (agent_setup.py owns this) rather than taxing Claude sessions with it. That relocation lever is UA-specific and the article doesn't cover it.

The Monday estate-wide usage assessment (2026-07-27, 90-day window, 187 skills desktop-side) found 143 cold skills and ~79% of ~28.7k standing skill-description tokens earning zero pulls. That assessment covered the desktop estate — the repo's own 95 project skills haven't had the same per-skill usage audit, and they load into every VPS session (Claude and GLM).

7 · Recommended execution order

  1. PR 1 (mechanical, no judgment): Tier 1 fixes + delete the triple-stated scratchpad copies + AGENTS.md restatements. Zero behavioral risk.
  2. PR 2 (editorial): de-archaeology + Key Commands + philosophy compression + pointer dedupe + heading demotion. Behavior-preserving rewrite; diff reviewed against the keep-list in Tier 3.
  3. PR 3 (measured): project-skill usage audit → archive the dead set. Gate on the repo's own Rule 1 invoker checks, not intuition.
  4. Later / optional: relocate GLM-only behavioral rules (e.g. Code-Verified Answers) from CLAUDE.md into the GLM lanes' SDK system_prompt, letting Claude-lane sessions run leaner. Requires an eval pass on a few GLM heartbeats before/after.
  5. Interactive check: run native /doctor in a claudereal session in the repo once, to catch anything the trim check flags that this audit missed.
