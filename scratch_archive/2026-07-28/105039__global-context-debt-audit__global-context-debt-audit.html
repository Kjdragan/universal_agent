1. The constraint: which model actually reads this

Before any trim recommendation, the question the article's 80% figure hides: who is on the other end? The floor of explicitness is set by the weakest reader, not the best one.

Verified, not assumed. ~/.bashrc:240–300 defines claudezai. It launches claude with $HOME intact and no CLAUDE_CONFIG_DIR override, exporting only the ZAI base URL and tier map:

export ANTHROPIC_BASE_URL="https://api.z.ai/api/anthropic"
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="glm-5-turbo"
exec claude "$@"

So a GLM-class reader loads this exact file, interactively, today. That single fact caps the entire audit:

  • Deletion is capped. Hard-won postmortem rules and non-obvious gotchas must survive verbatim — the weak reader can't re-derive them.
  • Relocation is not capped. This is the lever the repo audit under-used. A skill body is read by whichever model invokes the skill — so moving a rarely-fired procedure out of the global costs the weak reader nothing at the moment it needs it, while refunding every session that doesn't. Most of the savings below are relocation, not deletion.

Both accounts share one file (~/.claude-acct2/CLAUDE.md → symlink, verified), so there is no per-lane variant to hide weak-reader content in — short of moving it into the launcher.

5. Tier 3 — Keep for the weak reader

Do not apply the article's advice to these. Each is a postmortem, a machine-specific fact, or a routing table — none is derivable.

  • Email default recipient. Actively counteracts injected metadata: this very session's system prompt asserts a userEmail, and the rule exists because the account address is a hard-bouncing one that must never be used as a send target. A model without this rule follows the injected field. Also carries the per-recipient send rule from the 2026-07-18 403.
  • Git-state honesty. Validated during this audit — it stopped a false "broken reference" report (see T1 §not-a-defect). The branching half prevented a 10-commit PR contamination. Highest evidence-per-token in the file.
  • Shipping autonomy. A behavioral grant. No model can derive permission to merge without asking.
  • Spawning subprocesses — least privilege. Non-obvious security reflex with an explicit scope limit ("only at the trust boundary") that stops it from over-firing. Well-written; leave it.
  • VPS / inference routing. "Never pay raw API prices", GLM for background, systemd timers not Routines, AgentMail not the Gmail connector. This is "rich references" done correctly — a routing table into canonical docs, and the most weak-reader-critical content in the file.
  • notify-phone mechanics + "print the link on screen too." Machine-specific and a repeated real-world failure.
  • Commit author identity — the pre-remote reflex only. The includeIf guard cannot cover the moment before a remote exists. That's the keeper; the rest is explanation.

Two observations worth acting on:

  • The top four are the ones the hooks and CLAUDE.md nag about — quick-recap, efficient-fable, publish-to-scratchpad, stay-within-limits. The elevation mechanism works. That is an argument for keeping one copy of those rules (the hook), not three (T2-2).

8. Governance finding: none of this is version-controlled

~/.claude/ is not a git repository. There is no PR gate, no CI, no rollback, no history of who changed a global rule or when. What exists instead is ten ad-hoc backup files accumulated by hand:

CLAUDE.md.bak-215941                       settings.json.bak-20260724-233707
settings.json.bak                          settings.json.bak2-20260724-235015
settings.json.bak-20260724-123446          settings.json.bak-crosstalk
settings.json.bak-doctor-20260728-103948   settings.json.bak.loopwire
settings.json.bak-xtalk                    settings.json.preinversion.20260506-233230.bak

Ten backups is not a backup strategy — it is the symptom of needing one. The CLAUDE.md backup is 4 days stale, and it was only by diffing against it that the superseded account-fungibility rule in T2-4 became visible.

This is sharper than a nice-to-have: the estate has a standing "ship without review" autonomy grant that explicitly excludes anything unrevertable — and the global instruction file that contains that grant is itself unrevertable. Recommendation: git init in ~/.claude/ with a tight allowlist (CLAUDE.md, settings.json, hooks/, agents/) and everything else ignored — credentials, projects/ (4.9 GB), plugins/cache/, skills/ symlinks. Private remote, or local-only; even local-only converts every future edit from irreversible to trivially revertable.

10. Method & what was verified

Every concrete reference in the desktop global was checked against the filesystem rather than read for plausibility. Sizes were measured, not estimated:

  • Skill descriptions — parsed from each SKILL.md frontmatter, restricted to enabled plugins and deduplicated by name. Two earlier passes were discarded as wrong: one swept the plugin cache and counted 3,652 files across stale version directories; a second counted 302 skills by including three plugins that each check out a shared 17-skill tree while surfacing only their own subset.
  • Hook injections — by executing each SessionStart hook and measuring stdout, not by reading the scripts.
  • Skill usage — a 90-day scan of every session transcript in both accounts' project directories (4.9 GB), extracting Skill tool invocations. A first attempt using per-line JSON parsing was killed at its timeout and replaced with a parallel regex pass.

Token figures are chars ÷ 4 and are approximate; relative magnitudes are what carry the argument.

Two claims that first read as defects were withdrawn after checking against origin/main and re-running the normalizer — both recorded above, because "the rule caught it" is evidence about which rules deserve their tokens.

Nothing was modified. Every change proposed here to ~/.claude/ awaits explicit approval, per the constraint that the directory has no version control and no rollback. Companion audit (same method, one repo): universal_agent context-debt audit.
